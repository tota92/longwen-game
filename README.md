# 龙纹消消棋 🐉

> 三消 + 英雄技能 + 关卡战斗 + 轻 Roguelite 的 H5 竖屏网页游戏。
> 基于 **Vue 3 + TypeScript + Vite + Pinia** 构建，即点即玩、零后端依赖。

依据《龙纹消消棋-需求文档-V1.0》实现 **MVP 全量范围**：8×8 棋盘、6 元素、四消/五消技能石、3 名英雄、8 个遗物、第一章 10 关 + 第二章 5 关、3 种普通敌人 + 两阶段 Boss、3 关新手引导、结算与本地存档、核心爽感反馈。

> **V2 玩法深度化（已实施，见《龙纹消消棋-玩法优化方案-V2.0.md》）**：元素克制（弱点 ×1.5 / 抗性 ×0.5）、敌人重做（数值重调 + 护甲 + 污染/凝甲/狂怒）、技能石按 2×STO 定价、遗物扩充至 12 件并按流派抽取。核心目标：让"打弱点、抢输出、选流派"成为真实决策。

## 快速开始

```bash
npm install      # 安装依赖
npm run dev      # 启动开发服务器（http://localhost:5173，支持局域网真机调试）
npm run build    # 类型检查 + 生产构建（输出 dist/）
npm run preview  # 预览生产构建
npm run test     # 核心逻辑冒烟测试（109 项断言：棋盘引擎/数值公式/元素克制/护甲/狂怒/配置自洽）
npm run balance  # 数值审计：用真实引擎模拟 15 关（难度/决策质量/换英雄差异），见下
npm run check:visual  # 多视口布局校验（棋盘铺满度 / 提示浮层契约 / 面板裁切，仅开发期）
npm run icons    # 重新生成全套图标资源（SVG → 256×256 透明 PNG）+ 校验 + 接触表
```

> 生产构建体积约 **63 KB (gzip)** JS + **14 KB** CSS；图标资源独立为 62 枚 PNG（合计约 950 KB，平均 15 KB/枚）。
> 音效由 Web Audio 实时合成，无音频文件依赖。

## 玩法速览

| 机制 | 说明 |
|---|---|
| 核心循环 | 交换相邻宝石 → 三消攻击 → 连锁掉落 → 敌人倒计时 -1 → 敌人行动 |
| 元素克制 | 敌人标注「元素 / 弱点 / 抗性」：命中弱点 **×1.5**、撞上抗性 **×0.5**；与主战元素加成（+20%）乘算。6 元素都在棋盘上，打弱点不依赖英雄池 |
| 护甲 | 精英/巨化/Boss 拥有护甲，按「消除波」减免固定伤害（下限 1）——小消被惩罚，大消/技能/炸弹更值钱 |
| 技能石 | 4 连 = 小技能石（≈2 回合输出）、5 连 = 终极技能石（≈3.5~4 回合）、L/T 型 = 炸弹石（3×3 连锁爆炸）；点击技能石可主动释放（消耗 1 回合） |
| 英雄 | 1 主战（决定技能与元素 +20%）+ 2 支援（提供被动）；MVP：炎龙骑士 / 冰霜女巫 / 森林德鲁伊 |
| 遗物 | 每波胜利后三选一（候选保证跨流派），仅本关生效，最多 3 个；12 件遗物覆盖输出/控制/生存/规则四条流派 |
| 敌人 | 倒计时制；精英（每 5 关）/ Boss（每 10 关，两阶段 + 阶段转换全屏攻击 + 半血狂怒）；冰霜幽灵冻结棋盘、火蜥蜴污染棋盘 |
| 数值锚点 | 1 回合标准输出（STO）= **12**；普通敌人 HP ≈ 5~6×STO（68）；宝石攻击每章 +1，敌人 HP 按同速率成长；**当前为 V2.2 硬核档**（详见方案文档第 8 节） |

### 关键设计决策

- **动画零 JS 开销**：64 个宝石 DOM 以 `cell.id` 为 key 复用，位置由 `transform: translate(%,%)` 表达，行列变化时 CSS transition 自动补间；新宝石入场与消除动画使用独立 `translate`/`scale` CSS 属性，避免与定位 transform 冲突。
- **消除流程可编排**：`标记 popping → 播放动画 → commitClear → gravity`，每个 async 步骤通过 `sleep()` 对齐动画时长，回合流程线性可读。
- **冻结宝石分段重力**：冻结宝石视为固定障碍，将每列切分为段；仅与棋盘顶部连通的段接收新宝石，段间空洞在解冻后自动恢复（REQ-ENEMY-101 悬空固定）。
- **洗牌收敛保证**：随机重排 + 贪婪修复（改写匹配组元素）双保险，确保洗后"无现成消除且存在有效交换"，避免死局循环。
- **存档快照化**：每回合结束将战斗全量状态（含棋盘 grid）序列化进 localStorage；刷新/退出后从主界面"继续战斗"无损恢复。

### 工程实现

- **矢量源 → 位图产物**：图标以 SVG 矢量绘制（`scripts/icons/catalog/*`），构建时经 sharp 以 512 渲染后 lanczos3 降采样到 256，边缘锐利且复用共享构件（`scripts/icons/theme.ts` 提供徽章/宝石/徽记/UI 四族生成器与符号库）。
- **零 SVG 滤镜**：光晕/材质/明暗全部由多层渐变与半透明形状实现，渲染器无关、体积可控（平均 15 KB/枚）、运行时零解析开销。
- **类型安全引用**：构建时自动生成 `src/config/iconIds.ts`（图标 ID 联合类型），配置表与组件用 `iconId` 字段引用，拼写错误在编译期即被拦截。
- **自动校验**：`npm run icons` 逐枚断言尺寸 256×256、含 alpha 通道、存在完全透明像素、单文件 ≤80 KB；任一项失败即中断构建。
- **审查闭环**：脚本产出接触表 `scripts/icons/_sheet.png` 用于系列一致性审查，`_inspect.png` 用于单图标原尺寸细节复核。
- **移动端优化**：进入战斗前 `preloadBoardIcons()` 预加载 6 元素 + 4 标记，避免棋盘首帧闪烁；棋盘仅换 `src`，位置动画仍由 transform 补间承担。

## UI 设计系统

视觉方向：**东方魔幻纹章**——深紫虚空底 + 鎏金纹章 + 元素色光晕；标题用楷体（古风），正文用系统中文字体（可读性优先）。

### 层次原则：关键信息优先，游玩区最大化

战斗界面的信息按「顶部窄条 / 战斗展示区 / 游玩区 / 信息区」四段组织，棋盘是唯一的视觉重心：

| 区域 | 内容 | 设计取舍 |
|---|---|---|
| 顶部窄条 | 暂停 /（提示重开） / 关卡名 / 波次 / 回合数 | 不设边框卡片，避免与棋盘争夺视觉重量；教程提示被关掉后在此出现重开入口，不占棋盘 |
| 战斗展示区 | 双方立绘 · 血条 · 状态 · 行动意图 · 倒计时环 · 蓄力条 | 对齐式对阵布局，行高恒定（蓄力条常驻占位），出现/消失不顶动棋盘；矮屏自动压扁让位给棋盘 |
| 游玩区 | 8×8 棋盘 + 提示浮层 | 棋盘取「可用宽度 ∩ 可用高度」——剩余空间内能放下的最大正方形，不留白也不溢出；棋盘上无常驻控件 |
| 信息区 | 宝石图鉴 · 英雄技能 | 窄屏收成底部双 Tab（高度固定，切页不改变棋盘）；宽屏转右侧常驻栏 |

**提示浮层**（`TipBar.vue`）挂在棋盘方框（`.board-box`）内做绝对定位，覆盖在棋盘下沿之上：

- 提示出现/消失**不参与布局**，棋盘尺寸与位置一个像素都不变（`visual-check` 用「摘掉浮层前后棋盘矩形必须一致」做回归）；
- 浮层与提示条本体 `pointer-events: none`，只有关闭按钮可点，**压在宝石上也不影响落子/滑动**；
- 字号、内边距、尺寸用 `cqw` 随棋盘边长缩放，小屏棋盘不会被提示盖满；
- 关闭后的重开入口放在**顶栏图标按钮**（`ui_tip`，蓝调高亮），不放棋盘上——棋盘上任何常驻按钮都会盖住底行宝石、抢掉落子点击。`visual-check` 会断言棋盘方框内不存在常驻可点元素。

**棋盘优先的矮屏策略**：棋盘是正方形，边长取「宽 ∩ 高」，矮屏上真正卡住棋盘的是高度。
`≤760px` 高时进入矮屏模式，顶栏、间距与展示区依次让位（立绘 90→约 57px，行高与内边距收紧），
信息区高度不动（128px 是技能页不被裁切的下限）：

| 视口 | 棋盘边长（常规 → 矮屏模式） | 占屏宽 |
|---|---|---|
| 375×667 | 264 → **342** | 91% |
| 360×640 | 241 → **318** | 88% |
| 1440×640（宽屏） | 316 → **426** | — |
| 390×844 / 414×896 | 374 / 398（本来就吃满屏宽） | 96% |

多视口实测（`npm run check:visual`）：铺满度 = 1.000（棋盘边长 ÷ 剩余空间内最大正方形边长），
无水平溢出、无面板裁切、棋盘内无常驻控件。

### 设计令牌

全部视觉常量集中在 `App.vue` 的 `:root`，组件消费变量而非硬编码，便于整体调优与换肤：

```
颜色    --gold / --gold-light / --bg-deep / --bg-panel / --border-gold
文本    --text-1（主） / --text-2（次） / --text-3（辅助标签）
状态    --hp / --hp-player / --shield / --danger
节奏    --sp-1…--sp-6（4 的倍数） / --r-sm…--r-xl（圆角层级）
阴影    --shadow-panel / --shadow-raise / --glow-gold / --glow-danger
动效    --dur-fast / --dur-base / --dur-slow / --ease-out
字体    --font-title（楷体） / --font-body（系统中文字体）
```

数值展示统一挂 `.num`（`font-variant-numeric: tabular-nums`），HP / 倒计时 / 伤害 / 回合数在跳动时不左右抖动。

### 响应式与动效规范

- **移动优先**：竖屏单列，`100dvh` + 安全区适配；面板间距由容器 `gap` 统一控制，避免多处 margin 叠加成死角。
- **棋盘自适应**：棋盘容器声明 `container-type: size`，棋盘边长取 `min(100%, 100cqh)`——即容器内容框的实测尺寸，窗口/安全区/地址栏收放时自动缩放，不需要任何 `dvh` 减法常数。
- **宽屏（≥860px）双栏**：棋盘居左、按剩余高度收敛为正方形并铺满，右侧「宝石图鉴 + 英雄技能」常驻；内容限宽 1180px 居中。
- **提示浮层**：任何提示（教程引导 / 系统提示 / 关闭后的重开胶囊）一律覆盖在棋盘之上，不预留高度、不改变棋盘，见上文「层次原则」。
- **动效克制**：强动效仅保留给状态变化（技能特写 / 阶段转换闪白 / 遗物协同飘字），装饰性循环动效（法阵旋转、徽记浮动、宝石呼吸）在下方规则下全部让位。
- **无障碍**：接入 `@media (prefers-reduced-motion: reduce)`——关闭震屏与全部循环动画、把过渡压缩到 0.01ms，仅保留血量/胜负等必要状态反馈。

## 移动端适配与性能

- 竖屏单列布局（max-width 560px），`100dvh` + 安全区 `env(safe-area-inset-*)`
- `touch-action: none` 阻止棋盘滚动，Pointer Events 统一鼠标/触摸，支持点击与滑动两种交换手势
- 构建目标 `es2015`，Chrome/Safari/微信等主流移动浏览器兼容
- 动画全部 CSS 补间（transform/opacity/scale），无逐帧 JS；64 格响应式追踪开销可控
