## Boss 战玩法升级（用户反馈"boss 战太简单"）

**问题定位**：远古巨龙原本 `skill: { type: 'none' }`，除阶段转换全屏吐息（15）外只有每 5 回合一次普攻 12，HP 80+60，玩家几乎零压力；两个阶段体验雷同。

**新增机制（数据驱动，全部在 `src/config/enemies.ts` 的 `patterns` 配置）**
- `EnemyAction` 行动轮换：Boss 每次行动按序取招并循环（attack / freezeBoard / poison / burn / charge / drain）。
- 蓄力—打断：`charge` 招式进入蓄力状态，玩家在窗口内累计造成 `interrupt` 点伤害即打断，Boss 吃 `recoil` 反噬；否则释放 `releaseDamage` 大招。
- `window` 参数：蓄力打断窗口与阶段倒计时解耦（固定 3 回合），保证二阶段 cd 2 加速时窗口仍公平。
- 玩家负面状态：`battle.playerBurn / playerPoison`，回合结束结算（无视护盾）。
- 阶段差异化：`phaseAttack` / `phaseCountdown` / 每阶段独立 `patterns`；二阶段「狂怒」攻击 14→17、cd 3→2、加入灼烧。
- 每阶段第 1 招即蓄力，保证机制必然触发（初版把蓄力排在第 3 招，实测因阶段过快而永不触发）。

## 关卡设计优化（用户反馈"关卡需要优化，提升玩家体验"）

### 诊断出的 4 个问题
1. 第一章 4/6/8 关都是「2 只史莱姆」，7/9 关都是「3 只史莱姆」——60% 关卡时间在做重复的事，全章只有 1 种敌人素材。
2. 2-1 与 2-2 波次构成逐字相同（相邻同质）。
3. Boss 关只有 2 波 → 进 Boss 前只有 1 个遗物，局内构筑没有展开空间。
4. 第二章均值承伤 15.6% < 第一章中段 28.3%——玩家宝石攻击力 +50% 而敌人只 +10 HP，**成长曲线是负的**。

### 交付的 4 条设计原则（均有可执行校验）
1. 每关一个新东西（相邻关卡波次构成不得相同）
2. 锯齿上升（每 3 关一次喘息关：1-8 巨化之守、2-4 寒气渐浓）
3. 波次数 = 遗物经济（N 波 = N−1 遗物；正式 Boss 关固定 3 波）
4. 变体即谜题（狂暴=速杀 / 巨化=持久 / 迅捷=抢节奏 / 精英=数值墙）

### 关键实现
- **敌人变体系统**：`WaveEnemy.elite` → `WaveEnemy.variant`（`EnemyVariant`: namePrefix/hpMult/atkMult/countdownDelta/tint）。
  `ENEMY_VARIANTS` 定义 4 种预设；`createEnemyState` 应用倍率与倒计时偏移（`Math.max(1, cd + delta)`，与冰霜女巫被动叠加）。
  `EnemyState.tint` 驱动 EnemyPanel 的 `--tint` 自定义属性（头像边框 + 名字着色）。
- **关卡表重写**：`src/config/levels.ts`，15 关全部重排；第二章从「6/12/18/14/28」调整为「6/12/30/14/46」。
- **UI**：`LevelSelectView.waveNames` 显示变体前缀。
- **测试**：`scripts/smoke-test.ts` 新增 [12] 敌人变体 + [13] 关卡设计不变量（共 79 项）。
- **文档**：需求文档第 6 章重写（设计原则 / 难度旋钮 / 关卡表 / 难度曲线 / 变体表）；新增 REQ-LEVEL-006/007/010~014、REQ-ENEMY-103。
- **交付物**：`docs/关卡设计总览.html`（可评审的关卡总览页）。

### 难度曲线（承伤占玩家血量 %）

## 战斗界面提示区优化（用户反馈"提示会挤占遮挡游戏区域，且要支持手动关闭"）

### 诊断
1. **挤占**：教程提示 `.guide-row` 塞在 `EnemyPanel` 的 flex 流里（`flex-basis:100%` 换行），提示一出现面板就变高 → 棋盘被顶下移，小屏（667 高）会被 `overflow:hidden` 裁切。
2. **同类问题**：Boss 蓄力条 `.charge-row` 也是条件渲染，每次蓄力都会撑高面板 → 棋盘跳动。
3. **遮挡**：22 处 `addFloat(x, 'info')` 系统提示以飘字形式显示在棋盘中央（y=22%），多条同时出现时叠在一起盖住宝石。

### 方案
- **新建 `src/components/TipBar.vue`**：绝对定位于 `.board-wrap` 底部（棋盘居中后这里是下方留白），**不参与文档流** → 零布局挤压。棋盘区是 `overflow:hidden`，提示层被限制在棋盘区内。
  - 提示条本体 `pointer-events:none`，只有关闭按钮 `auto` → 即使小屏上与棋盘下沿重叠也不挡落子。
  - 支持手动关闭；教程引导关闭后留一个「提示」胶囊可重新打开（`reopenTip`）。
  - 两类消息：`tutorial`（常驻，蓝色）/ `system`（自动消失，金色，`ANIM.tip = 2600ms`）。
- **store**：新增 `tip` ref + `showTip`/`dismissTip`/`reopenTip`，派生 `activeTip`（系统提示优先于教程引导）与 `hasHiddenGuide`；`BattleRuntime.guideDismissed`（仅本关有效，startLevel/continueBattle 重置）。
- **`addFloat` 路由**：`kind === 'info'` 一律转 `showTip`，不再盖棋盘。飘字只保留 damage/crit/skill/heal，且 y 从 22%/78% 改为 **13%/88%**（伤害贴敌方区、治疗贴我方区）。
- **`FloatLayer`**：位置改用 `--fx/--fy` 自定义属性 + 宽屏媒体查询（≥860px 时飘字跟随右列信息栏，不再落在左列棋盘上）。
- **`EnemyPanel`**：删除 `guide` prop 与 `.guide-row` 及样式；新增 `canCharge()`，蓄力行改为**常驻容器 + `min-height:17px`**，蓄力条出现不再改变面板高度。
- **`BattleView`**：`<TipBar />` 放入 `.board-wrap`。
- `constants.ts`：`ANIM.tip = 2600`。

### 验证
- `npm run typecheck` 通过；冒烟测试 79 项全通过。
- 未跑 `npm test`/`npm run build`（esbuild 环境问题，同前）。

### 遗留
- `PlayerPanel` 的 `.buff-row` 仍是 `flex-wrap: wrap`：拿到第 3 个遗物时在窄屏可能换行 → 我方区变高、棋盘位移。若要彻底消除布局抖动，可改成 `nowrap + overflow-x:auto`（代价是遗物名需横滑查看）。

## 界面四项优化（战斗展示区 / 立绘 / 宝石区 / 技能区）

### 设计取舍（重要，后续别推翻）
- **技能"等级"= 1 + 强化该技能的遗物数**（上限 `SKILL_LEVEL_MAX = 1 + MAX_RELICS = 4`）。
  不新增独立技能等级，避免与遗物这条唯一成长轴互相稀释。
- **技能"冷却时间"在本作不存在**（技能由四消/五消生成的技能石即时触发）。
  用「触发条件 + 棋盘现有技能石存量」表达可用状态，比虚构倒计时更贴合玩法。
- **宝石"等级"= 熟练度**，按本局累计消除量分级（`GEM_LEVEL_THRESHOLDS = [0,6,14,26,42]`），

### 关键修复（踩坑记录）
1. **Vue 3.4 的 `compileTemplate` 不再支持 `scopeId` 选项注入 `data-v-xxx`**。
   自建构建通道（`scripts/preview-build.mjs`）里必须用 `compilerOptions.nodeTransforms`
   手动给 `node.type === 1 && node.tagType !== 3` 的节点 push `{ type: 6, name: 'data-v-xxx' }`，
   否则页面完全无样式。
2. **`.panel` 的 `backdrop-filter` 会给 `position: fixed` 后代创建包含块** ——
   宝石/技能详情浮层被困在底部面板的 128px 里。修法：浮层用 `<Teleport to="body">`。
3. **战斗舞台 `align-items: end` 导致两侧错位**：怪物侧多「意图 + 蓄力」两行，
   底部对齐会把立绘整体顶上去，名字/血条不齐。改为 `align-items: start` + `.center-col { align-self: end }`。
4. **`dealDamageToEnemy` 里英雄出手/怪物受击的动作切换与命中特效曾被并发编辑覆盖丢失**，
   表现为血条掉了但角色一直 idle。已补 `setActorAction` + `spawnHitFx`，
   并加 `source: 'hero' | 'dot'` 参数区分主动出手与灼烧/中毒持续伤害。
5. **棋盘尺寸不要用 `100dvh` 减魔法常数**：安全区、地址栏收放、横屏都会改变可用高度，减法必然对不准。
   改为 `.board-wrap { container-type: size }` + `.board { width: min(100%, 94vw, 100cqh) }`。
6. **提示条会压住棋盘最后一行**：`TipBar` 绝对定位在棋盘区底部，需预留 `--tip-h: 58px`
   （宽屏 `.board-wrap` 的覆盖规则也要带，否则宽屏漏掉）。预留而非动态让位 → 提示出现/消失棋盘不跳动。
7. **手机横屏棋盘会塌成 2px**（可用高度不足）。加纯 CSS 横屏守卫：`App.vue` 的 `.rotate-guard`
   + `@media (orientation: landscape) and (max-height: 520px)` 隐藏 `.screen-host`，提示转回竖屏。

### 布局常量（改布局只需动这几处）
- `--bottom-total: 128px` = Tab 栏 25 + 技能页内容 86 + 内边距间距 17。
  这是**技能页不被裁切的下限**，两页取同一值保证切 Tab 时棋盘尺寸不变。矮屏只差 3px 棋盘，不值得压。
